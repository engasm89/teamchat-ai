# CTO code-review Q&A — answer only with actual verified evidence

1. **Why PostgreSQL instead of Firestore?** Composite tenant keys, transactionally ordered room events, row-level security, class/coefficient joins and durable outbox; NOTIFY is only a wakeup, the durable event log is truth. Trade-off: dedicated LISTEN connection per API instance and contention on room sequence row.
2. **Where is authorization enforced?** Firebase ID token verification -> restricted UID/tenant lookup -> room membership checks -> transaction-local PostgreSQL tenant context and forced RLS; workers resolve ownership server-side. Need actual SQL probes for acceptance.
3. **Can Gemini pick another tenant?** Tool declarations expose no tenant argument; executor is constructed with server-resolved context. Saved memories and prompt injection cannot change RLS. Real adversarial test is mandatory.
4. **How do cross-instance sockets sync?** State/event commit in PostgreSQL, NOTIFY opaque room token, instance LISTEN wakes its own subscribers, authoritative replay by monotonic room sequence. No session affinity assumption. Test actual two instances.
5. **What happens with duplicate sends?** Stable `clientMessageId` deduplicates durable message; conflicting payload should be rejected; client retains pending sends across transport reconnect. Two-browser replay proof needed.
6. **Why no direct token stream from Gemini?** Model prose may contain invented product codes or monetary claims; only validated database-backed answer blocks are shown progressively, with visible native function-call traces.
7. **How is store score derived?** Explicit *assumption*: distinct mapped margin classes, remove superseded classes transitively, sum retained margin coefficients for segment, multiply by channel/format coefficient, compare before-after. Not a sales forecast. Null classes unscored. No monetary value without validated user-provided baseline.
8. **Why does ST-4003 show zero change for some codes?** Fixture already carries class 318; adding another product in same class does not change distinct-class coefficient score. The synthetic financial model cannot infer sales demand.
9. **How does memory avoid lexical-only failures?** Server-generated Vertex embeddings, per-tenant filtering and lexical/semantic retrieval, saved provenance and original author/time/source room; exact query paraphrase needs live test.
10. **What if Gemini tries an untrusted instruction from a saved note?** Treat tool text/memory as untrusted data and only present facts fetched through a scoped tool. Model cannot grant permissions.
11. **AI crash mid-turn?** Durable job, Cloud Tasks idempotency, lease fencing, stored plans/results, answer-reset event and client projection; inspect retries end-to-end before claiming success.
12. **How do you avoid memory leaks?** Bounded WebSocket connections/buffers, cleanup of timers/subscriptions on close, client lifecycle teardown, bounded transcript, shutdown signal handling and closed Cloud Tasks clients. Must profile/verify on live service.
13. **What parts deliberately remain out of scope?** Direct messages, rich editor, file uploads, admin console, SSO, billing and production multi-region failover, as explicitly disclosed in the submitted brief.
14. **What was modified since the brief?** Seven tools now include side-by-side assortment comparison; automatic monetary value was withdrawn without a verified user baseline; retry, replay and security hardening evolved. Document each divergence honestly.
15. **What is proven today?** Only original brief submission, dataset integrity, offline tests, TypeScript check with temporary Node types, and source-level safeguards. Do not say live RLS, model streaming, React build or two-instance recovery passed until the IDE agent actually records evidence.
16. **What did the CTO ask for above implementation?** Architecture clarity, scalable modular responsibilities, no memory leaks, parallel engineer ownership; explain `src/server`, `src/worker`, `src/persistence`, `src/retail`, `apps/web`, `db/migrations` boundaries.
